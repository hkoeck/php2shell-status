## Key facts

- **Fixed upstream** in PHP **8.5.12, 8.4.27, 8.3.36, 8.2.35** (21 Oct 2026). All earlier versions are affected (sources say back to PHP 5.4). PHP 8.1 and older get no release; the PHP security team published **minimal source backports for 7.4, 8.0 and 8.1** (CERT-EU), and distributions/LTS vendors ship their own backports.
- **Related, not fixed yet: CVE-2026-115560** (23 Oct). Only if an application switches `session.serialize_handler` from `php_binary` / `php_serialize` to `php` at runtime before `session_start()` while session upload progress is on. The 21 Oct releases do not fix it. PHP ([advisory](https://www.php.net/archive/2026.php)): "We suggest you set `session.upload_progress.enabled=0` until the next regular bugfix release, to fully protect from an unlikely RCE vector." **Keep it at 0 after patching.** No CVE record, NVD entry or KEV entry yet (27 Oct). Vendor statements are in the rows (F5, Palo Alto, Quest, LibreNMS, Red Hat, Cloudflare).
- **Regression in 8.4.27 / 8.5.12** (not in the security fixes): [php-src #24488](https://github.com/php/php-src/issues/24488), GC double free of the SimpleXMLElement properties table (`zend_mm_heap corrupted`) when the properties were materialized (`get_object_vars()`, `(array)` cast, `json_encode()`); "It passes on 8.4.26." Fixed in commit [f963484](https://github.com/php/php-src/commit/f9634847258a8c3ed6c12bb79104eba60bb631ea) (22 Oct), not in a release yet. Do not roll back to unpatched versions; test SimpleXML-heavy applications.
- **Not PHP2Shell:** the PHP Windows builds `-1` (26 Oct) only add Brotli 1.2.1 for CVE-2026-111497; "the PHP runtime versions remain unchanged".
- **Severity:** CVSS v4.0 **9.2** (PHP) · NVD CVSS 3.1 **9.8** (109618) / **8.1** (109619) · Red Hat / SUSE / Amazon **8.1 (Important)** · Ubuntu **Critical**.
- **Most exposed:** Apache **mod_php** (RCE validated with default limits). 109618 on FPM: "susceptible" by source analysis, no complete exploit shown; **109619: RCE validated on mod_php and FPM** (PHP GHSAs). FrankenPHP likely susceptible, LiteSpeed LSAPI conditional.
- **Exploitation – treat as exploited:**
  - **CISA KEV:** both CVEs added on **26 Oct**, due date **29 Oct** (BOD 26-04) ([catalog](https://www.cisa.gov/known-exploited-vulnerabilities-catalog)). CISA SSVC in the CVE record still says "Exploitation: none".
  - **Successful shells:** Adel Karimi ([report](https://github.com/0x4D31/honeypot-data/blob/main/reports/php2shell/2026-10-24-confirmed-rce.md), 24 Oct) shows "35 complete execution-stage HTTP POSTs with 35 `/bin/sh` starts directly parented by Apache workers" on three PHP 8.4.26 `mod_php` honeypots; "it is not a measurement of exploit reliability on other worker counts, PHP builds, or applications". [Trail of Bits](https://x.com/trailofbits/status/2114839775173906751) (26 Oct): demo shell on MediaWiki, Symfony, Laravel and phpBB.
  - **Attempts in the wild:** Amazon (first attempt in MadPot honeypots on **17 Oct**, four days before disclosure; investigate from 17 Oct), Cloudflare, watchTowr, [Zscaler](https://www.zscaler.com/blogs/security-research/cve-2026-109618-and-cve-2026-109619-php-vulnerable-unauthenticated-rce) (1,156 attempts from 156 IPs against 70 organizations in the first 48 hours), Imunify360 (exploit tool reached more than 3,600 servers by 11:00 UTC on 21 Oct). [Unit 42](https://unit42.paloaltonetworks.com/cve-2026-109618-cve-2026-109619/) retracted its 23 Oct report of a government case on 25 Oct.
  - **Public PoCs:** several, each tied to a specific OS / PHP / web-server combination; Rapid7: "none appears to be broadly reliable"; Sansec cites a researcher: public PoCs "do not work against a default PHP installation". Typical request: multipart upload with `PHPSESSID` and `PHP_SESSION_UPLOAD_PROGRESS` fields and hundreds of parts or a multi-megabyte fill field (Datadog); one tool uses the boundary `----shellflow-php2shell` (Zscaler: "should not be considered durable").
  - **No exploitation seen** by BSI, Canada CCCS, Talos (21 Oct), Cisco PSIRT, Juniper SIRT, or Palo Alto against its products.
- **Forensics:** Mandiant: "capture worker memory before patching or rebooting, as restarting workers permanently destroys volatile heap evidence". Sophos: the PHP project got the first reports on 11 Aug; review exposed systems from **1 Aug 2026** (multipart POSTs to non-upload endpoints, `PHP_SESSION_UPLOAD_PROGRESS` in requests, memory-exhaustion errors, worker segfaults, admin logins).
- **Mitigations are partial:** `memory_limit=-1` (109618) and `session.upload_progress.enabled=0` (one 109619 path) are incomplete; watchTowr calls `.ini` mitigations "ineffective"; Sophos adds `fatal_error_backtraces=0` on PHP 8.5. **Only patching closes both bugs.** WAF rules (section 2) are defense-in-depth.

## Checking whether you are patched

With backports, `php -v` keeps showing the old version. Check package versions or changelogs:

```sh
# Debian / Ubuntu (adjust php8.x)
zgrep CVE-2026-109618 /usr/share/doc/php8.4-fpm/changelog.Debian.gz
# RHEL / Alma / Rocky / Oracle / SUSE / Amazon Linux
rpm -q --changelog php-fpm | grep CVE-2026-109618
# Remi
dnf list --updates --refresh --repo remi-modular
```

Restart PHP-FPM after updating; for mod_php do a full Apache restart. Rebuild container images; updating the host does not update PHP inside an image.
